# 0.6.2 安卓启动加载优化

2026-10-17，Godot 4.7.2，Android versionCode 602。

测试包：`export/android/convoy-v0.6.2-arm64-test.apk`，87,325,132 字节（约87.33 MB）。SHA-256：`ff9e0420d87f0e2cf1fa799539b3f2c416609ee420d8a9f62e7843172abf0390`。沿用现有测试签名和包名，可覆盖安装，不需要卸载或清除数据。

## 调整原因

Android 15 实体手机反馈0.6.1加载数分钟仍停留在0%。源码检查确认：主菜单静态预载了完整游戏场景；菜单、游戏规则及资源集中在一个后台加载请求中；隐藏的设置页和第二个视频播放器也提前创建；加载器仅在15秒后更换等待提示，没有超时退出。

这些是已确认的实现问题。隔离模拟器未复现实体手机数分钟卡住，因此不能把具体线程死锁或设备兼容问题认定为已证实根因。

## 实现

- 菜单只准备自身资源，游戏场景和规则在选择新游戏或存档后加载。
- 图片、视频、音乐分别后台读取，按实际资源进度和完成数量显示阶段进度；不使用随时间自动前进的假进度。
- GDScript和场景的初始化放回主线程，先绘制遮罩，再装配界面，避免后台脚本依赖加载与主线程初始化争用。场景切换同样先预热图片，再在主线程装配场景。
- 设置页面保留即时可用的偏好值，界面及额外视频播放器在首次打开设置时创建。
- 单项资源30秒没有进度变化时显示超时提示与重试；即使持续有变化，单项读取最长等待120秒。重试接续已存在的读取请求，不为同一资源重复启动任务。Godot不提供取消该后台请求的接口。
- 启动日志增加资源读取、菜单装配、首帧就绪的毫秒时间，保存在应用自身的`user://startup.log`。

主线程装配阶段仍是同步操作，不提供可中断超时；本轮已把完整游戏和隐藏设置页从菜单阶段移出，降低这一阶段的工作量。

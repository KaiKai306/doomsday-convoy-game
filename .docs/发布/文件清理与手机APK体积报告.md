## 移出的内容与保留原则

- 约 5.44 GiB 的制作源包、中间帧、重复 ZIP、旧导出、原生视频、绿幕预览、文稿渲染等移出工程；现有 Markdown 实际引用的图片与正式文档保留。
- 约 701 MiB 的历史 QA 输出、测试产物及失去存活导入侧车的孤立 Godot 缓存移出工程。
- “新车辆追加”中的制作环境与源资产约 398 MiB 移出工程，包括随素材带入的 Python / OpenCV；游戏当前使用已安装到 assets 的资源。
- assets 内约 89 MiB 的绿幕 GIF 总览和动作预览移至归档；正式透明 PNG 动画帧、SpriteFrames、场景和静态素材库均保留。
- 根目录分析摘录、一次性脚本、旧日志及车辆检视图移至归档。
- 保留全部正式脚本、规则数据、设计最终总稿、第三方许可、车辆入景参数及真实玩家存档。未删除 src/core 历史代码，因为主菜单仍使用其中的 GameState。
- 坐姿动画虽尚未进入当前正式场景，仍属于已制作的素材库，保留在工程中；当前 APK 导出范围不包含这些未启用的动画。
- 开发 / 美术资料和工具目录加入 .gdignore，避免再次把工具输出当游戏素材导入。第三方许可另随资源包保存。
- 两处指向已归档预览的 Markdown 链接已改为归档相对链接；其修改前版本也已保存。

## 后续压缩建议（均未实施）

1. **先试地图导入压缩。** 两组主地图约占包内 990 MiB，远高于视频。可以在保留原 PNG 的前提下，另做 ETC2 / Basis 等 Android 纹理导入压缩样张，比较透明边缘、暗部细节、首次加载和真机内存。ASTC 的设备支持需另评估。实际收益必须以重新导出与设备测试为准。
2. **再评估背景分辨率。** 宽屏层常见 2752×1216；单层解码为 RGBA8 约 12.8 MiB，三层约 38.3 MiB，不代表完整进程峰值。缩至约 2048 宽可降低约 45% 的像素量，但当前行走与层定位会读取纹理尺寸，不能直接批量缩图或设置 size_limit，否则可能改变现有构图与锚点；需单独验证，当前不做。
3. **无损 PNG 重编码只能先测。** 保留像素的重新编码可能缩小工程源文件，但 Godot 会再次导入为 .ctex，不保证 APK 同比例减小。不能把“PNG 少了多少”直接当作包体收益。
4. **视频和 BGM 放后面。** 当前实际使用的背景视频约 2.27 MiB，BGM 约 2.94 MiB。旧标题视频约 3.43 MiB，目前作为保留素材；它们不是主要体积来源。Theora 曾有转码器兼容问题，若之后调整必须完整解码并在 Godot 实测循环。
5. **透明图片不批量转 JPEG。** 人物、车辆与前景图层依赖透明度；转换会损伤现有显示。任何有损方案都先给手机样张和体积对比，再由用户决定是否替换。

本轮没有执行以上压缩方案，也没有扩大游戏功能。

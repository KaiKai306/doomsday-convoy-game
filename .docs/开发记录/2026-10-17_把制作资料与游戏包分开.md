# 2026-10-17｜把制作资料与游戏包分开

这轮暂停玩法开发，先整理越来越大的工程。最初目录约 10.08 GiB，但其中大部分是制作过程留下的内容，不是玩家真正需要下载的游戏。

## 先分清楚哪些文件有用

源视频、绿幕 GIF、逐帧中间图、重复交付包、模型试验和 QA 截图混在一起。单是相同的动画交付 ZIP 就出现了两份，每份约 248 MiB。车辆源包里还带着一套 Python / OpenCV 环境。

筛选时没有直接以“没找到固定路径引用”作为删除依据。地图、头像、车辆会动态拼接路径，坐姿动画虽然尚未接入，也属于已经制作好的素材库。因此先核对运行入口和资源清单，再区分游戏资源、正式素材库和制作中间产物。

最终将 17,444 个文件、约 6.61 GiB 移出工程并保留恢复归档。工程约降至 3.48 GiB，正式图片与动画帧没有压缩，源素材也没有永久丢弃。开发记录实际引用的图仍留在原位置，少数已移动的预览改为归档链接。

## 工程缩小不等于安装包已经够小

整理后按 Android 的打包范围导出原画质资源包，实测仍约 1.22 GiB。继续检查才看到：两组主地图在包内合计约 990 MiB，而当前背景视频只有约 2.27 MiB。

这说明后续如果需要降低手机端下载量，优先对象应是地图纹理。仅把 PNG 无损重存一次，或者先压小背景视频，都未必解决真正的包体问题。用户选择本轮保留原画质，因此这里只列建议，没有换编码、缩图或损伤透明边缘。

## 清理也需要验证

清理前后对保护文件做 SHA-256 核对，保留了正式代码、规则、剧情、车辆参数与玩家存档。八组回归的结果一致；原本三项横屏 HUD 越界断言仍然存在，本轮没有扩大到布局修改。

导出清单需要显式覆盖动态加载的 JSON 与地图，还要避免把原素材目录和旧试验一并塞进去。从实际资源包启动后，主菜单、新游戏和车辆页通过 952 项包含与运行检查，图形也做了复核。第三方许可跟随游戏包保留。

当前只是 APK 打包准备与体积审计，没有正式签名、生成 APK 或进行真机测试。详细清单、恢复方法和压缩建议见 [清理与 APK 体积报告](../发布/文件清理与手机APK体积报告.md)。

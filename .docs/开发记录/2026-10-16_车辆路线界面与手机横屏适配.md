# 车辆、路线界面与手机横屏适配

## 本轮范围

接续“继续当前对话任务 (2)”中断的界面工作：车辆页沿用车辆卡片，路线页采用可选节点与实时行程报价；成员、物资、知识岗位、阵营、目标、记录、对话、暂停和确认窗口统一采用主页的暖金文字、半透明底与 ARWES 切角边框。手机适配期间保留另一对话按用户要求完成的精简：点击车辆后打开五个改装槽，再选择配件。用户随后要求所有页面去掉底部整排导航，本次已统一删除导航条、按钮及“自动存档”提示；地图与各管理页从顶部“菜单”切换。

用户本轮确认：手机横屏，兼容常见手机比例。门口交互由其他对话负责，本轮未修改进入内屋的条件、坐标和保存规则。

## 手机适配

- 基准窗口改为 1600×720（20:9），画布使用 `canvas_items` 与 `expand`，根据设备比例扩展逻辑画布。
- 将原来的竖屏方向配置修正为 `SCREEN_SENSOR_LANDSCAPE`，允许手机左右两种横屏方向。
- 背景与三层场景等比铺满屏幕；世界场景和触控界面分别适配，人物不做非等比拉伸。原图和场景坐标保持原有数据。
- `src/ui/mobile_layout.gd` 将系统安全区从屏幕像素映射到逻辑画布，避开刘海、手势区及屏幕边缘。主页、设置、管理页、场景界面、摇杆、交互按钮、确认窗和加载提示共用这套计算。
- 车辆页和地图页的主要操作随可用高度移动，按钮为48逻辑像素；所有管理页取消底部导航，顶部提供“菜单”。菜单内以两列大按钮切换页面。车辆详情与配件弹窗也位于安全区内。
- 切换比例时中止旧的入场位移动画，避免动画把菜单拉回上一种尺寸的位置。
- 接入上个对话已生成但未引用的 `garage_clean_source.png`，移除背景中未编入车队的整车。保留 DeepSeek 原始文件、生成记录与素材清单。

## 运行预览

双击 `tools/启动手机横屏UI预览.bat`。预览读取正式存档副本，自动保存到独立的 `management_design_preview` 目录。

- F1：车辆管理；F2：路线地图；F3：当前行程；F4：主页。
- F5：循环切换16:9、19.5:9、20:9、21:9、22:9窗口。
- 晨间准备之前可以查看地图；出发仍需满足现有规则。

## 验证

初次手机适配的525项检查全部通过。统一移除底部导航后重新进行 Godot 图形验证：手机适配303项、管理界面181项，全部通过。管理界面覆盖地图、车辆、成员、物资、知识岗位、阵营、目标、记录各页的顶部菜单和触摸切换；手机适配覆盖七种窗口尺寸，含2340×1080、960×432以及模拟刘海、顶部留白与底部手势区。

检查背景覆盖、界面和确认窗安全区、非等比变形、坐标映射后的地图与顶部菜单点击、真实触摸事件驱动摇杆、滑出控件后的松手、对话锁定移动，以及切换尺寸和浏览不改变游戏状态。最新日志为 `.godot/mobile_menu_only.log` 与 `.godot/management_menu_only.log`。

证据位于 `.docs/美术/手机横屏适配_20261016/`；`verification.json` 记录窗口与实际逻辑画布、模拟安全区及测试结果。此处为桌面端按手机尺寸渲染与触摸事件验证，尚未做 Android/iOS 真机安装测试。

车辆在各场景的用户确认参数未被本轮更改；本轮没有将车辆加入新的场景。

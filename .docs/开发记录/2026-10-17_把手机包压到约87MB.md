# 2026-10-17｜把手机包压到约 87 MB

整理制作文件后，原画质资源包仍有约 1.31 GB。继续拆包才看到，主要体积来自地图纹理的无损导入，两套地图合计接近 1 GB。手机包的优化重点因此放到了图片导入和导出范围。

先保留原图分辨率，试用 Godot 的有损导入。背景和人物、车辆分开设置质量，小图标继续保留。场景图原本几 MB，重新导入后不少降到了几百 KB。第一版实际 APK 约 123 MB，证明效果很明显，也说明只量图片大小还不够，必须把引擎一起打包测量。

之后把场景纹理调整到 0.4、人物和车辆等细节图保留 0.8。这里没有缩图，因为现有场景会从纹理读取尺寸，直接降低分辨率可能影响行走坐标、图层和已经确定的构图。逐张核对 511 张压缩纹理，尺寸不变，透明通道逐像素一致；颜色细节允许有一定损失。

另一部分收益来自更准确的导出清单。角色姿势预览、旧车辆模型、旧地图整图预览和界面拼图源表不需要跟着玩家下载。但文件名不能作为判断依据：有些叫 source 的图片正被正式界面使用，需要保留。核对菜单后，也确认旧标题视频已被设置页背景替代，可以排除旧标题图和视频。最终排除了 54 项资源，原件仍留在工程里。后两次清单优化分别省下约 7.49 MB 和 3.73 MB，不需要继续降低画质。

最终资源包约 61.14 MB，比原画质基准减少约 95%；含 ARM64 引擎和测试签名的 APK 实测约 87.31 MB。100 MB 只作为参考，取舍依据是手机观感与实际收益。

验证从导出的资源包启动菜单、新游戏和车辆页，再遍历 53 张正式横版地图，检查图层、坐标和相机覆盖，并复看森林、雪地、室内与车辆页截图。原始素材、代码、场景和数据的哈希核对通过。已有的三项横屏 HUD 适配断言仍待单独处理，本轮没有改动布局。

这次解决的是下载包体，图片分辨率未降，因此运行时内存不会按相同比例缩小。测试包已完成签名和完整性检查，实际安卓设备的字体、触摸与内存表现还要真机确认。参数、实测过程与恢复方式见[手机资源压缩实测](../发布/手机资源压缩实测.md)。

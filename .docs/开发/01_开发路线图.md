# 《末日车队》开发路线图

## 阶段 0：工程准备（已完成）

- 确认 Godot 4.7.2.stable。
- 创建 Git 仓库、`.gitignore` 和 `.gitattributes`。
- 创建可启动的 Godot 项目与最小主场景。
- 保留现有三份策划文档及图片目录，建立开发文档索引。
- 主菜单已按图册版式建立 2D 占位界面；正式背景不引用现有示例图。

## 当前 Demo 目标

先完成一个可在手机横屏上操作的 Demo：主菜单 → 新游戏 → 第 1 天早晨 → 路线选择 → 移动结算 → 停歇对话 → 营地行动 → 夜间结算。界面按照图册中的排版、层级和信息密度制作，背景先使用纯色、渐变、几何块面和临时图标。

Demo 不要求完整美术、完整战斗、十三种结局或所有设置页；只要玩家能完成一轮，并看见资源、事务和因果变化，就达到当前阶段目标。

## 阶段 1：第一条可玩循环

目标是让玩家完成“第 1 天：早晨 → 选路线 → 移动 → 停歇 → 对话 → 营地行动 → 夜间结算”。

实现顺序：

1. 全局状态：天数、阶段、资源、成员列表、车辆状态和事件日志。
2. 早晨面板：显示资源、成员、车辆和当天 2–3 条 NPC 事务。
3. 路线选择：安全 / 资源 / 未知三条路线，先用固定数据。
4. 移动结算：进度条、燃料消耗和一种即时突发（道路事故或怪物群二选一）。
5. 停歇对话：一个 NPC、三种回应（接受 / 拒绝 / 延期），结果写入事件日志。
6. 营地行动：先实现“维修”或“阅读”中的一个，并产生可见状态变化。
7. 夜间结算：展示因果链、扣除每日资源，进入第 2 天。

## 阶段 2：第一个垂直切片

- 1 条主路线、5 个停歇点。
- 初始队长 + 4 名成员，成员数值差异先固定。
- 徒步 / 轻型车辆 / 大型车辆三个阶段先以状态切换表达。
- 4–5 种资源、1 种主要怪物行为、10–12 天循环。
- 4–6 个可验证结局，优先覆盖继续流动、稳定定居、资源耗尽、成员死亡和知识保存。

## 阶段 3：内容扩展

在循环稳定后再加入：六种休息点场景、交易与谈判、书籍传播、茶叶与香薰仪式、更多即时突发、车辆升级路线和 13 种图册结局插画。

## 每阶段验收标准

- 可以从主菜单开始并完成一轮流程。
- 每个选择都能在当天或夜间结算中看到结果。
- 重新启动后不会依赖编辑器临时状态。
- 所有新增系统都有一条最小可重复测试路径和对应的开发文档记录。

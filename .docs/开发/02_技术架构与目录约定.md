# 技术架构与目录约定

2026年10月15日0.6.0，当前正式入口使用 `src/game` 二十天规则，旧 `src/core` 保留为历史实现。

## 入口与职责

|位置|职责|
|---|---|
|`scenes/main.tscn`、`src/ui/main_menu.gd`|主菜单、动态背景、设置、开始与继续|
|`scenes/release_game.tscn`、`src/game/release_game.gd`|八功能页、行动预验、确认框及自动保存|
|`src/game/rules.gd`|基础状态、资源、人口、岗位、路线、救援与结局|
|`src/game/card_rules.gd`|事件候选、选项结算、营地替代与设备|
|`src/game/world_rules.gd`|继承以上规则，补地图、期限、固定主线、实物货载与环境事件；当前调用入口|
|`src/game/presentation.gd`|按状态选择对白、日程、尾声与玩家可读名称|
|`src/game/camp_walk.gd`|侧视走动与交谈，不独立发放资源或扩充行动|
|`src/game/save.gd`|存档校验、临时文件替换与备份|
|`data/final/content.json`|最终Word导入的结构化内容|

`tools/import_final_manuscript.py` 导入内容并记录原Word哈希。规则调整对照总稿，不能改测试数据绕过实际门槛。本轮收尾未修改总稿Word。

## 状态与命令

常规阶段为 `morning → route → event（有事件时）→ stop → camp → camp_event（有事件时）→ night`。第10日插入 `rescue` 和必要的 `rescue_seats`；群体冲突使用 `split`，终局为 `ending`。

界面统一调用 `command(action,args)`。执行失败恢复先前状态及随机状态；行动预验执行后同样恢复快照。玩法收益和成本放在规则层，按钮不自行支付或跳日期。

当前状态 `s` 包括资源、成员、车辆、位置、历史、事实与当日使用标记；`day_start` 是晨间快照。普通终局先记录完成意图，再经过夜间配给和伤亡检查；即时死亡和当前无解优先。

## 存档

schema为1并校验最终总稿哈希。载荷包含 `current` 与 `day_start`；继续恢复前者，重试恢复后者并更换种子。随机状态用字符串保存，防止JSON丢失64位精度。

写盘先生成带SHA256封装的临时文件，旧文件转为备份后替换。编辑器存档在 `.godot/player_saves/saves`，导出运行写入 `user://saves`。旧十日格式不当作本版进度读取。

## 界面与验证

逻辑画布1280×720，按视口等比缩放居中，正文和行动列表独立滚动。不可逆选择及整日重试使用确认框。营地按触点记录方向，左右抵消，释放与失焦清理输入；键盘通过动作映射支持A/D与E/空格。

`tools/check_final_game.ps1` 顺序运行新版五组测试；`-GraphicalUI` 增加渲染检查，`-FindEndingPaths` 增加路线搜索。固定结局资料在 `tests/fixtures`，不依赖 `.godot` 缓存。详细结果见[验收清单](06_Demo验收清单.md)。

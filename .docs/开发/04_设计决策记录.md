# 设计决策记录

## 2026-10-11：个人状态与地点取舍

- **个人状态**：五人分别记录健康、疲劳、信任和最近记忆。全队信任继续独立记录，疲劳摘要为五人的四舍五入平均值。
- **受伤与疲劳**：道路事故伤老赵，绕行可减轻；高追踪遭遇伤阿遥。赶路改变全员疲劳，阿遥因侦察额外 +3。个人疲劳 ≥70 时夜间健康 -5；基础成员健康归零在夜间触发失败。
- **事务生成**：健康缺口与疲劳共同决定医疗目标；先按紧急度稳定排序，再取最多三条。老赵个人信任 ≤30 时优先生成维修分配冲突。完整群体关系与离队尚未实现。
- **治疗**：医疗事务消耗一份药品治疗指定成员（健康 +20、疲劳 -15）；营地照料也消耗一份药品（健康 +25、疲劳 -10、个人信任 +3），占用当晚行动。
- **地点**：五处地点各两项固定、可预览的行动，不额外增加免费探索次数。地点选择与维修、阅读、教学、照料、休息共用一次行动；结果保存资源、个人负担、追踪与选择事实。
- **界面**：营地用当地发现 / 常规行动 / 照料成员三个入口，成员总览暂停移动和行进。受伤队员在侧视场景显示健康条。
- **存档**：版本 2 增加可选成员数组；旧存档缺数组时，按原全队疲劳与信任初始化每个人。新成员字段与事务医疗目标会在恢复前验证。

## 2026-10-11：对话回到侧视营地

- **决定**：自动行进保持俯视表现，停歇对话切换侧视营地；队长可以走动，靠近队员再打开请求。
- **原因**：图册把休息点走动和交谈作为核心体验，单纯阶段面板缺少营地中的空间关系。
- **事务顺序**：继续按当前优先事务顺序处理；其他队员可以先查看近况，不绕过队列。结束交谈不自动算作延期，回应后回到探索。
- **输入**：点按地面为移动目标，屏幕方向支持多指；桌面保留动作映射。松手、切出窗口、暂停或进入交谈会清理按住状态。交谈期间规则层禁止移动。
- **存档**：沿用版本 2，增加营地位置和打开对话两个可选字段。旧版 2 从入口恢复；打开对话的存档必须满足当前说话人的距离条件。
- **范围**：本轮只完成探索与交谈的基础连接，地点仍是程序绘制标记，没有额外探索掉落、场景碰撞机关或完整自由事务排序。

## 2026-10-10：五日玩法验证与真实效果

- **决定**：当前 0.2 是五日带车体验切片，包含五处地点标记；完整版本仍按原策划保留徒步起步、车辆成长和 12–20 天旅途，不把体验结果当作完整结局系统。
- **原因**：原先界面效果与状态不一致。先验证真实资源、耐久、疲劳、知识、成员请求和夜间因果，才能评估游戏中的选择是否成立。
- **影响**：每日命令检查阶段与资源，营地行动和配给只能结算一次；真实消耗优先于把负数钳成零后继续奖励。
- **路线**：三条路线有各自补给；低噪音 / 快速 / 绕行预设改变追踪、疲劳、事故率和损伤。移动自动进行约七秒，事故直接按预设结算。
- **对话**：逐条处理当天事务，昨天的维修与情报结果生成不同后续请求；低饮水 / 高疲劳插入后勤 / 医疗事务，最多三条。
- **涌现最小例子**：阅读手册后两次教学与记录形成共同维护习惯，每晚耐久 +3。路线知识不能替代手册阅读。完整个人知识传播尚未实现。
- **生存规则**：库存不足以支付本晚配给才结束；库存正好够当晚时允许下一天寻找补给。任一路线都无法支付燃料时提供明确结果入口，避免界面卡死。
- **存档**：格式版本 2 保存新增状态、事务游标、行进进度与随机状态；拒绝版本 1 和损坏数据，验证完成前不修改当前游戏。
- **界面**：统一主题，程序绘制可替换场景，不使用策划示例图；主要推进按钮、移动预设和消耗摘要固定显示。
- **开发记录**：按用户要求写入 `.docs/开发记录/`，记录可用于发帖的实现过程和效果，不写接手或交接过程。

## 2026-10-07：建立 Godot 开发基线

- **决定**：使用 Godot 4.7.2 stable；项目设置以横屏安卓为目标，开发期保留键鼠输入。
- **原因**：图册明确写明安卓横屏和触屏操控，策划案的键鼠字段更适合桌面调试，不应反过来决定产品交互。
- **影响**：UI 通过动作名和信号工作，后续可以替换触控布局而不改每日循环规则。

## 2026-10-07：先做每日循环垂直切片

- **决定**：第一阶段只实现一天循环和固定数据，不先做完整战斗、十三种结局或全部六种休息点场景。
- **原因**：三份文档都把 NPC 对话、资源分配和夜间因果链定义为主要玩法；先验证这个闭环可以尽早发现节奏和状态结构问题。
- **影响**：战斗暂作为移动阶段的一种即时突发占位；结局先覆盖 4–6 个可测试状态。

## 2026-10-07：设计原文与开发结论分开管理

- **决定**：不直接改写现有策划原文；新增结论统一写入 `.docs/开发/`，图片仍使用原文旁的 `_media` 目录。
- **原因**：保留策划版本的可追溯性，避免实现讨论破坏示意图册的图片链接。

## 2026-10-07：Demo 先做 2D 手机端版式

- **决定**：当前目标改为手机横屏 2D Demo；先复刻图册的版式、层级和交互区域，暂时不使用图册中的背景图片。
- **原因**：先验证玩法循环和界面信息是否成立，避免临时背景绑定正式美术资源。
- **影响**：主菜单和后续界面使用占位几何元素；正式背景通过独立资源槽替换，不改交互逻辑。

## 2026-10-07：首个 Demo 范围确认

- **决定**：首个 Demo 同时包含中文主菜单和一天完整循环；界面文字统一使用中文。
- **原因**：主菜单是完整进入流程的一部分，一天循环用于验证核心玩法是否成立。
- **影响**：验收顺序为“主菜单 → 新游戏 → 早晨 → 路线 → 移动 → 停歇对话 → 营地行动 → 夜间结算”。

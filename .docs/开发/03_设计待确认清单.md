# 设计待确认清单

这些问题不影响工程骨架，但会影响第一条可玩循环的内容和数值。建议先回答带“阻塞阶段 1”的项目。

| 优先级 | 问题 | 当前默认值 | 影响 |
|---|---|---|---|
| 阶段 1 | 首个可玩版本是否以安卓触屏为正式基线？ | 是；开发期兼容键鼠 | UI 尺寸、输入、教学提示 |
| 阶段 1 | 四名初始成员的岗位和姓名是什么？ | 暂用队长、维修、医疗、侦察、后勤五个角色 | NPC 日程和工作效率 |
| 阶段 1 | 第一种即时突发先做什么？ | 道路事故 | 移动阶段的最小实现 |
| 阶段 1 | 第一天允许几条 NPC 事务？ | 2–3 条 | 对话队列和教学节奏 |
| 阶段 1 | 资源是否采用饮水、食物、燃料、药品、零件五项？ | 是 | 每日消耗与结局判定 |
| 阶段 2 | 车队人口上限和招募条件是什么？ | 待定 | 招募、资源压力、结局 |
| 阶段 2 | 第一版做 4–6 个结局，还是直接覆盖图册 13 种？ | 4–6 个 | 内容量和验收范围 |
| 阶段 2 | “信任”是全队单值，还是成员 / 群体分别记录？ | 建议成员关系 + 全队信任两层 | 对话结果和涌现结算 |

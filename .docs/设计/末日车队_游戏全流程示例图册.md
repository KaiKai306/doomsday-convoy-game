# 《末日车队》游戏全流程示例图册 · 正式定稿

2026年10月14日。保留原60张媒体及其原图号，图18继续留空；每张图的文字需求已经按[定稿规则基准](./定稿规则基准.md)重写。原图片中文字、人物名、数值、车辆数与旧交互仅作视觉参考，正式开发按本文说明制作UI，不从图片反推规则。

平台：安卓横屏单机，HD-2D。旅途与状态面板俯视；营地走动、交谈、谈判侧视。五人一旧车出发，最多8人/2车。八个固定重要日为2、5、8、10、12、15、18、20，第10实际救援最重要；第5固定正式求救，救出后继续。主结局17个，加独立妹妹命运尾声。

本图册交付界面、镜头和交互规范；游戏代码与新插画生产另行实施。图片路径、尺寸、顺序与既有素材保持一致。现有图37–49共13张结局参考；缺的4个正式主结局已在附录给完整镜头文字，插画待制作，不是剧情待定。

## 玩家操作顺序

1. 图09启动→图10标题→图01主菜单；图02–08设置。
2. 图11新游戏或继续→图12序章→图13第1日教学。
3. 每日图50早晨→图51/15路线→图52/16自动旅途；图17及58–61即时事件。
4. 图23/31–36停歇探索→图24/53/56人物事务；图25分配、图26–28真实交易；图29/57结果。
5. 图14/19整备与岗位培养、图54营地一次行动→图55夜结算和结局检查。
6. 未结束继续下一日；第12日起可真实完成目标提前收束；第20夜兜底。图37–49和附录覆盖17主结局，另附妹妹命运。
7. 图20暂停→图21查看自动进度/重试当天；图22退出。继续保留已抽结果，重试恢复日开始并重新抽本日随机，不修改此前历史。

## 图 19　岗位培养与车辆配件

## 妹妹尾声与关键日界面补充

妹妹尾声不是额外主结局：救后存活、救后死亡、确认死亡、失联、主动放弃、获救未随行。可用角色/物件小镜头加文字附在全部17主结局后，选择实际成立的一项；失联不能伪写死亡。

第10日图31/51扩展为救援核验页：情报3、南线承诺、至少6主边、主车耐久≥40、油≥12、零件≥5、药≥2、医疗/侦察≥60且健康≥50疲劳≤70、水食各≥min(8,N+1)。低声救援基础成本及正面突破额外零件2/耐久10同时可见；满足条件成功100%，不放生死转盘。满8人救援成功后登记前，选现有队友经同意留已确认安全接纳点并列明物资移交，才登记妹妹；失败不提前驱逐。未选择离队时由已确认照料者安置妹妹，记获救未随行；不得隐藏人口超载。

第12/15/18/20日图31/51扩展为实际目标动作页：真实到达、真实登记、贡献、买车、建点与最后行进。门槛不足显示缺项，已满足多个结局不展示结局名称列表，而按最后完成的实际行动核验。正常入口至少8条主边；入口余下6千米含在当日完成行动，不再重复收油。

失车图14/15/25扩展为保留货重与期限页：健康≥30每人8千克，重伤每人2千克；普通徒步10千米、水2N食N、疲劳20、危险60%，潜行40%，强赶路80%并疲劳额外15。第12前持续徒步最晚12夜；后期min(失车日+1,20)夜。具体地图点、换车成本零件6油10与不可追回丢物明确显示。

普通隧道避风点不是N-C04出口完全封死的通道。实际到达已标封死入口且仍准备穿越时，N-C04物理危机100%；可以沿来路退回、弃车或修外侧退路，强冲会同批全员死亡。第10救援站隔离走廊另有独立现场因果，不能使用同一封死隧道却结算不同伤亡。

正常结局镜头统一在完成动作锁意图、当晚配给和死亡/即时无解检查之后出现；即时死亡结局当批出现。第9岑柏固定100%占机会槽，满员加入锁定。存档载荷day_start/current分别用于整日重试和继续，本日死亡与招募也随整日重试撤销；安全离队妹妹按最后确认真实状态写尾声。

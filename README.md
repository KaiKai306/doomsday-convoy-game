# 末日车队

面向安卓横屏的 2D 末日生存经营与叙事决策游戏，使用项目自带的 Godot 4.7.2 stable。

当前是 **0.4 五日体验切片**：五个人带一辆旧车出发。每天完成准备、选路、自动行进、营地探索与成员对话、一次营地行动和夜间结算。完整版本的徒步起步、车辆成长和 12–20 天旅途尚未实现。

## 运行

用本目录的 `Godot_v4.7.2-stable_win64.exe` 导入 `project.godot`，运行主场景 `scenes/main.tscn`。

- 三条路线分别提供安全通行、物资补给和路线档案。
- 出发前选择低噪音、快速或绕行；车队约七秒后自动抵达。
- 抵达后切换到侧视营地；点按地面移动，或按住屏幕左右方向。镜头跟随队长。
- 靠近队员后点按交谈，按优先队列逐条回应请求；可以先查看其他队员近况。
- 交谈期间停止移动；结束交谈可以原地继续探索，不会把请求自动记成延期。
- 选择前可看到代价和次日影响；桌面调试支持 A / D 移动、E 或空格交谈。
- 成员各有健康、疲劳、个人信任和最近记忆；顶部显示平均疲劳。成员状态按钮可以查看详情，打开时暂停移动。
- 事故会伤到老赵，怪物追踪会伤到阿遥；高疲劳每晚损失健康。医疗请求指出具体伤员，营地也可选择定向照料。
- 五处停歇点各有两种当地行动：旧泵燃料 / 备件、隧道药品 / 罐头、水塔抽水 / 搬水、雪地搜索 / 保暖、山口口粮 / 档案。
- 当地发现、常规行动和照料成员共用一次营地行动；选了补给就放弃同晚维修、阅读或休息。
- 常规行动先选读者、教师与学员或维修执行者；选择过程中可以返回，不消耗当晚行动。
- 阅读技术手册让指定成员掌握维修知识；教学由已掌握者教给另一位尚未掌握的成员，成员详情保存来源。
- 阅读、教学和维修参与者须健康 >0、疲劳 <70；教学双方个人信任须 >30。没有合适人选时可照料或休息。
- 维修消耗零件 2，普通成员恢复耐久 15，掌握维修知识者恢复 21（上限 100）；每晚只做一次主要行动。
- 至少三位不同成员掌握，并完成两次教给新学员的教学，才形成共同维护习惯，之后每晚耐久 +3。重复阅读或教学不增加进度。
- 五日可获得“仍在路上”或“知识的火种”结果；配给不足、车损、信任、疲劳或无法出发会提前结束。
- 暂停菜单保存 / 读取，主菜单继续游戏；存档包含行进进度、事务游标、营地位置与打开的对话。

存档版本已升为 2，旧版 1 存档不兼容，会提示重新开始。资源不足时不会免费执行行动。所有场景仍为程序绘制占位，没有把策划图册当作正式背景。

0.4 继续兼容 0.2 / 0.3 的版本 2 存档。旧存档没有营地位置时从入口恢复；没有个人数据时补全成员，原有全队疲劳与信任迁移到各人的对应字段。

个人知识也沿用版本 2。旧档没有知识字段时，根据原阅读、教学和共同维护进度补全老赵及不同学员；新档记录真实读者与教学来源，损坏字段会在恢复前拒绝。尚未执行的成员选择不写入存档，读档后回到正常行动入口。

## 目录

- `scenes/`：主场景与每日体验场景。
- `src/core/`：状态、阶段命令、内容读取及存档。
- `src/ui/`：界面、主题和可替换场景绘制。
- `data/demo_content.json`：成员、路线、事务、营地动作、五处地点和结果文案。
- `tests/`：规则与 UI 流程验证。
- `.docs/设计/`：原始策划与图册。
- `.docs/开发/`：实现约束及设计决策。
- `.docs/开发记录/`：供 Game Jam 帖子使用的开发过程与截图素材。
